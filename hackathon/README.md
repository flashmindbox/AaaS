# Hackathon Kit

Everything the team needs to pitch, demo, and defend AaaS at the table.

**Positioning:** Odisha-first, Odia-first. The live demo is in Odia, the target pilots are in Odisha, and the state's 5T / Mo Sarkar programmes are the policy anchor. The technical plan for Odia (typography, speech stack, dyslexia rules, pilot partners) is in [`docs/odia-language-strategy.md`](../docs/odia-language-strategy.md) — read that before the first pitch.

| File | Read it when |
|---|---|
| [`PITCH.md`](./PITCH.md) | Preparing what you will *say*. Has 15-second, 60-second, 3-minute, 5-minute variants. |
| [`DEMO_SCRIPT.md`](./DEMO_SCRIPT.md) | Preparing what you will *show*. Scene-by-scene narration and fallbacks. |
| [`JUDGE_QA.md`](./JUDGE_QA.md) | Preparing what you will *answer*. 25+ anticipated questions with crisp replies. |
| [`PRESENTER_BRIEF.md`](./PRESENTER_BRIEF.md) | Carry in your pocket. The one-pager with numbers, phrases, and safe moves. |
| [`BOOTH_CHECKLIST.md`](./BOOTH_CHECKLIST.md) | The day-of checklist. Pack list, setup order, fallback triggers. |

## How to use this kit in the week before the hackathon

**Day -7.** Read all five files. Rehearse the 60-second pitch aloud.
**Day -5.** Run the full demo end-to-end. Time it. Run it again.
**Day -3.** Rehearse with someone outside the team watching. Ask what confused them.
**Day -2.** Record the demo as a video fallback. Print the brief and checklist.
**Day -1.** Pack, sleep, don't add features.
**Day 0.** Work the checklist. Trust the prep.

## Principles under all of this

1. **Honesty beats hype.** Judges have seen every vaporware pitch. A smaller, real demo wins.
2. **Speak to the human before the tech.** Priya, Arun, Meera before IndicTrans2, Whisper, Piper.
3. **Design the demo around what cannot fail.** If one layer of the stack is flaky, don't demo it.
4. **Every conversation ends with an ask.** Without an ask, a good conversation produces nothing.
